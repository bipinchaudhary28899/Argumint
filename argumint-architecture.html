Key Features

🎯 Dual Debate Modes

Alternate: Ordered turns with per-turn countdown. Buzzer: Free-for-all grab-the-mic with re-grab windows.

🔊 Live Audio over WebRTC

Direct peer-to-peer audio mesh between participants. Socket.IO only carries SDP offers/answers and ICE candidates for signalling.

🗣️ Smart Transcription

Web Speech API as primary path with OpenAI Whisper fallback for reliable argument capture.

🤖 AI Judge System

GPT-4o-mini scores arguments on 4 axes (clarity, evidence, rebuttal, organization) and determines winning side with feedback.

👨⚖️ Human Judge Credibility

Pro rooms support human judges with 6-pillar credibility scoring (rank agreement, consensus, consistency, alignment, confidence, bias).

📈 XP & Levelling System

10-tier ladder from Novice to Grand Master. Separate XP tracking for debaters and judge credibility scores.

🔐 Cross-Device Auth

JWT in localStorage enables authentication across origins (Vercel frontend + Render backend) without third-party cookies.

💳 Pro Subscriptions

Razorpay-backed recurring subscriptions unlock Pro features. Webhook-driven status sync.

🎫 Single Active Session

Redis enforces one session per user. Logging in elsewhere prompts before evicting stale session.

📱 Mobile Responsive

All screens optimized for mobile viewports with in-app-browser gate for unsupported webviews.

🏆 Leaderboards

Global leaderboard, per-user debate history, judge statistics, and detailed match analysis.

💰 Cost Tracking

Each debate records Whisper minutes, judge token counts, and computed USD cost for spend observability.

Data Flow: Complete Debate Lifecycle

Step-by-Step Execution Path

1
Create Room
Host calls POST /rooms/create with motion, mode, rounds, turn duration → Server generates 6-char room code → Room document created in MongoDB with status 'lobby' → Redis stores session
2
Join & Ready Up
Players POST /rooms/join with code → Each player connects Socket.IO → Emits room:join → Server broadcasts room:participant-* events to all clients → Players toggle ready with room:update-status
3
Optional Voting Phase
Host can run room:start-voting → Clients vote via room:vote-topic → Server aggregates votes → room:end-voting finalizes motion or defaults to original
4
Start Debate
Host emits room:start-debate → Server randomly assigns FOR/AGAINST to each participant → Builds turn order → Creates Debate document in MongoDB → Broadcasts debate:started to move everyone to prep screen
5A
Alternate Mode: Turn-Based Speaking
Server broadcasts debate:turn-started with speaker ID and endsAt timestamp → Speaker's audio flows peer-to-peer via WebRTC → Live transcription via Web Speech API or fallback to POST /debates/transcribe (Whisper) → Player emits debate:submit-argument → Server broadcasts debate:turn-ended and advances turn
5B
Buzzer Mode: Grab-the-Mic
Mic is open. Player emits buzzer:grab → Server uses Redis lock to atomically assign floor → Broadcasts buzzer:holder-changed → On buzzer:release or timeout, opens re-grab window (buzzer:window-open) for few seconds → buzzer:warning keeps UI synced with countdown
6
End Debate & Judge
When all turns finish or host emits debate:host-end → Server assembles full transcript → Calls judge.service → Sends transcript to OpenAI GPT-4o-mini → AI returns per-speaker scores (4 axes), winning side, feedback → Server broadcasts debate:result-ready with scores
7
Human Judges (Pro Rooms)
If room has human judges → Server broadcasts debate:scoring-window-opened → Judges submit scores via debate:submit-judge-scores → Judge emits debate:lock-judge-scores → credibility.service computes 6-pillar score per judge and updates rolling credibility
8
Results & XP
Results page shows leaderboard, per-axis breakdowns, winning side, XP awarded → User stats (wins/losses), xp, and judgeStats are persisted to MongoDB → Client updates local cache → Player can view match history via GET /auth/history
